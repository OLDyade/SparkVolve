# 让 Harness 自己进化

## Evolve the Harness, Not the Model.

不改模型权重，让 Harness 在任务中持续进化。

**一句话定位：** 一个基于插件化架构的 Harness 自进化框架，让 Agent 通过真实任务反馈，自主改造自己的能力结构，并将有效改进沉淀为可复用的插件。

核心记忆点不是“Agent 越用越聪明”，而是：

> 过去我们给 Agent 装能力，现在让 Agent 自己决定需要什么能力、修改什么能力，甚至创造新能力。

## 三个核心设计

### 1. 插件即进化基因：让 Harness 从“人工装配”走向“自主重构”

不再局限于 Prompt、Skills 优化，而是把插件的配置、代码实现、组合拓扑统一作为进化对象。

能启停、能调参、能替换、能重组，还能创造新的插件。

这是最值得投入研究的技术创新点。

### 2. 进化也是插件：给已有 Harness 装上自进化能力

不需要重新造一套 Agent Runtime。基于 DSH 原生插件体系，将优化器、实验控制、执行验证等能力装配到现有环境。

不是创造一个会进化的 Agent，而是让已有的 Harness 具备进化能力。

这是非常适合开源生态传播的产品创新点。

### 3. 进化成果也是插件：从实验分数到可安装的能力

自主发现问题、修改插件、验证收益，最后不只得到一个更高的 Benchmark 分数，还输出可安装的 Bundle、候选谱系与复现实验。

让一次进化的收益，成为其他开发者可直接复用的能力。

这是区别于仅展示优化曲线的研究原型的交付创新点。

## 核心指导与设计责任

上述核心思想与原句作为项目基调保留。以下六条列出当前明确的方向约束，属于开放、非穷尽的指导；它们不构成完整需求清单，也不限制后续提出更好的技术设计。后续指导继续累积，出现冲突时明确讨论并记录调整依据。

| 不可妥协的原则 | 典型跑偏表现 |
|---|---|
| 1. 插件是进化基本单元 | 最终只会修改 Prompt 或 Skills，没有插件实现、配置和组合结构的进化 |
| 2. 基于 DSH 原生插件生态 | 重新造一套独立 Agent Runtime，用 DSH 只做包装 |
| 3. 真正的自主进化闭环 | 优化器只是反复调用 Benchmark，或者开发者事先写死了优化策略 |
| 4. 独立、可信的实验验证 | 修改评测规则、泄漏答案、挑选有利题目，或者只有一次分数提升就宣称成功 |
| 5. 进化成果可复用 | 只输出一个优化后的运行目录或配置，无法安装成真正的能力 Bundle |
| 6. 通用框架优先，Excel 是首个场景 | 大量逻辑写死在 SpreadsheetBench，换个任务就得重写进化系统 |

用户提供方向、目标与关键裁决；承担设计与实现的 Agent 负责主动补足生态研究、架构、接口、搜索机制、实验协议、可靠运行与交付细节，并通过实际证据自我审查。不能将未被逐项提醒的问题遗漏，也不能以照抄指导代替技术判断。未知或可能过时的机制先核实；发现设计与核心思想冲突时，说明原因和取舍。

实验系统明确数据权限、预算与评判规则；优化器在这些边界内依据真实反馈选择问题、父版本与变异方案。通用进化机制与场景适配分开设计，插件安装、运行及复用效果分别验证。

## 项目全景：从接入进化能力，到自主重构，再到插件交付

三个核心设计贯穿同一闭环：②—④把进化能力接入已有 Harness，⑤—⑫由任务反馈驱动插件自主重构，⑬将验证后的成果交付给开发者，并为后续进化积累可复用资产。
