Subsequent acceptance has been extended to continuous mutation, real dual-session continuation, independent paired re-validation, and research asset reuse; see [Full Product Closed-Loop Acceptance](acceptance-continuous.md). The original results and failure records from the earlier run are retained below.

On 2026-10-27, using Venus `deepseek/deepseek-v4.1-flash-1017` with thinking off, native DSH autonomous mutation, independent execution and scoring, negative-result adjudication, and a real task after Bundle installation were completed. The experiment used publicly available synthetic XLSX files generated by the repository and does not represent historical SpreadsheetBench results.

Machine-readable record: [run identity, per-task results, invocation and package hashes](evidence/2026-10-27-real-acceptance.json). Implementation commit: `f3042c6`; actual DSH release version: `0.2.1-rc.4`.

## Actual Results

| Fixed task | Baseline score | Mutation score | Baseline / mutation duration | Delivered formula count: baseline / mutation |
|---|---:|---:|---:|---:|
| operating-plan | 100% | 0% | 16.479 / 11.547 s | 14 / 0 |
| regional-plan | 100% | 0% | 21.269 / 11.557 s | 14 / 0 |
| stress-plan | 100% | 0% | 16.037 / 12.881 s | 14 / 0 |

Both groups completed 3/3 with 0 execution failures, and original input content retention was 100% in both. The candidate recompute tool replaced formulas with computed constants; numeric matching still does not satisfy the task's formula delivery requirement, so independent scoring was zero. The system retained the baseline and did not promote the candidate because it ran faster or because the model claimed validation passed.

The baseline actually invoked `workbook_inspect`, with one task invoking `workbook_write`; all three candidate tasks actually invoked the new tool `workbook_recalculate`. Complete request records confirm that these tools entered the model schema. This result proves that native mutation and the feedback loop actually executed; **it does not prove an accuracy improvement**.

The optimizer wrote and tested a revised draft `verify-readonly` on its own, then received an explicit rejection because the candidate budget was exhausted. The revised draft was not evaluated and is not recorded as a successful candidate. The contract and original report of each experiment remain unchanged.

## Failure Records and Corrections

- The first Provider assembly inserted the default plugin repeatedly, and the real request was not sent; after switching to native configuration override, a separate experiment was started.
- One optimizer reached the 900-second budget without completing candidate submission. The original failure is retained; the host recovered from the persistent request ledger 165 starts, 164 returns, 1 incomplete. Subsequent contracts use 1800 seconds and inform the remaining budget through native context.
- An early spreadsheet plugin used an incorrect nested-parameter DSL, and DSH disabled it as an optional plugin. The full score that group of models obtained via Shell cannot certify that the plugin took effect. The author interface was fixed, and acceptance was re-run using actual Cordis activation instead of syntax checking; the corresponding old report was not rewritten.
- One host installation check was interrupted by an outer 20-second command timeout, and the above tool was found not activated; that run is not recorded as a successful installation. The final installation acceptance used an independent run directory, full container lifecycle, and independent scoring.
- pnpm installation, platform binary scripts, and Bundle activation failures were corrected according to the actual causes; directly mounting source code was not used as a substitute for the final native installation acceptance.

Original trajectories and workbooks are stored locally in `.evolution/` and are not committed to Git. The public record retains identity and results; the full process can be re-run from Quick start, and model sampling results may differ. The baseline of the three synthetic tasks has already reached full score, so separately pre-registered discriminative data and re-validation are needed to study score improvement and transfer.
