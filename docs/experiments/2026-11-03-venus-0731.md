# Venus 0731: separate provider availability from Harness quality

The operator selected Venus Chat Completions, model `deepseek/deepseek-v4-flash-0731`, after the official account exhausted its balance. This is a new provider contract and a new experiment. No official-provider result is reused or pooled.

## Frozen route

- Endpoint: `https://venus.xfinfr.com/v1/chat/completions`.
- DSH: `0.2.1-rc.4`; native `llm-pi-ai` Chat adapter.
- Requested effort: off; native wire setting `enable_thinking: false`.
- Context declaration: 1,000,000; output cap: 32,768; task budget: 600 seconds.
- Adapter retries: zero. Credentials remain broker-owned in a private environment file.
- The relay may route among suppliers. A requested model name does not independently attest weights, supplier identity or equivalence to the official endpoint.

## Verified before the study

A real native SDK session through the credential broker called `sum_integers`, replayed its result and returned 95. Two adapter attempts completed, with zero failed or unfinished attempts. Reported input/output: 21,291 / 160 tokens; adapter stream durations summed to 6.827 seconds. Cache usage was absent and remains unknown. This is connectivity and tool-replay evidence, not benchmark-quality evidence.

A network-isolated native test inspects the exact outgoing model, output cap, streaming flag, off-mode setting and tool replay. Controller tests inject a typed rate-limit failure and verify that remaining tasks are cancelled, no candidate is selected, no new proposal is admitted and reopening the controller does not resample.

## Availability boundary

The request ledger retains DSH's structured error code. Authentication, account quota, rate limiting, server, transport, request timeout and empty-response failures interrupt the experiment. The original failed run and full task denominator remain visible, with `qualityComparisonValid=false`; no quality decision is made and no automatic retry is added.

Task/formula/tool mistakes are still ordinary evolution evidence. Invalid requests, context-window overflow and unknown adapter errors are not automatically classified as upstream faults. They require attribution from the actual request and runtime evidence. Error-message keywords are never used as a classifier.
