# 同一个优化器，任务反馈能带来什么

本次真实模型试验将比较同一冻结 G 在两种宿主反馈协议下生成的 Harness。目标是观察自主变异行为、独立任务质量和实际成本，补上确定性容器验收无法回答的问题。**此文先于模型执行写入；实际合同、镜像、源码和构建身份由驱动生成的注册记录冻结。未记录终态前不报告结果。**

这是一项有限的描述性研究。它不替代[更大范围的 E/B/R 研究设计](../research/2026-10-28-feedback-causal-protocol.md)，也不以获胜或正收益作为验收通过条件。

## 固定对象与唯一比较变量

| 对象            | 注册定义                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------- |
| 优化器 G        | `optimizers/evidence-driven` 的同一源码、锁文件、构建产物和原生装配；两组提示说明与工具相同              |
| 初始 Harness H0 | `examples/spreadsheet/seed` 的同一冻结 Bundle，两组及独立基线复用原构建产物                              |
| 模型            | Venus `deepseek/deepseek-v4.1-flash-1017`，G/H 均 thinking off，单次最大输出 32768；完整合同记录模型配置 |
| Full 臂         | 授权任务输入、源码、构建、装配、执行轨迹、交付、评分；`seed-only + full`                                 |
| Mechanical 臂   | 授权任务输入、源码、构建及原生装配；隐藏任务执行反馈和冠军选择；`seed-only + mechanical`                 |
| 共同修改空间    | 启用、停用、调优、替换、组合与创造插件；每个变异均从 H0 分叉，允许跨插件协同修改                         |
| 共同边界        | 固定任务、模型、评分、预算、隔离和构建；禁止题目特判、预写答案、猜测后处理及评测修改                     |
| 共同关闭        | 研究资产库、行为探针、研究者领域 QA；原生装配 QA 保留                                                    |

G 的通用说明明确两种反馈协议、原始输入入口及 `candidate.settled` 语义。该说明在两组中逐字相同，避免机械组因等待不存在的事件停滞。优化器自己选择变异机制，不由驱动生成修改方案、公式或补救程序。

## 数据、重复与执行上限

采用已公开的 `examples/spreadsheet/research.py` 全部四个家族：归一化利润、加权组合、债务滚动、场景估值。搜索使用 development，独立评估使用 validation。生成器、原评分器及每份输入／评分目录摘要进入合同。

这些家族在本项目此前已使用；validation 改变同一家族中的数值，不代表未知模板、跨领域迁移或官方 SpreadsheetBench 成绩。评分材料只供独立评测进程使用；优化器不接收 validation 输入、交付或分数。

```text
同一 G、H0、模型和搜索任务
       │
       ├─ 配对块 0：Full-0 ↔ Mechanical-0
       │                 │
       │          每臂 H0 + 最多 2 个变异
       │                 │
       │          共同宿主规则选择冻结 H*
       │                 │
       │          各自独立评估 4 个任务
       │
       └─ 配对块 1：Mechanical-1 ↔ Full-1
                         │
                  全新搜索目录与会话
                  相同预算、独立产物和评分

共同 H0 ── 独立 validation 4 题 × 2 次
                         │
               逐搜索均值 + 配对差值 + 全量成本
```

| 预算项           |                          上限 |
| ---------------- | ----------------------------: |
| 独立搜索         |               2 臂 × 2 次 = 4 |
| 每次搜索候选     |           H0 + 2 个新变异 = 3 |
| 搜索任务执行     | 4 次搜索 × 3 候选 × 4 题 = 48 |
| 所选 H* 独立评估 |          4 次搜索 × 4 题 = 16 |
| 共同 H0 独立评估 |               4 题 × 2 次 = 8 |
| 合计任务执行     |                            72 |
| 优化器时间分配   |      4 次 × 1200 秒 = 4800 秒 |
| 搜索实例并发     |                 每块最多 2 个 |

以上不包含构建、装配 QA、独立评分及 G 自身的请求次数。它定义相同分配上限，未宣称相同实际 Token、费用或墙钟耗时。候选不足、提前结束、构建失败及服务失败均保留，不补抽、不重试、不按结果调整顺序。普通质量并列保留 H0，按宿主原有规则选择 H*；不会自动发布或推广能力包。

配对块的顺序在运行前确定：按注册臂顺序随重复编号轮转，两个臂对应 AB／BA。块内使用相同并发上限；前块终态后开始下一块。计划和实际派发事件均保存。并发下 AB／BA 指入队次序，准备容器及首笔模型请求的实际先后以事件为准，不承诺严格同步起跑。这样避免把某种反馈模式完全绑定到独占时段，仍不能消除供应商负载、缓存及共享宿主资源噪声。

## 分析与失败处理

- **统计单位是完整独立搜索，每臂只有 2 次。** 每个产物的 4 道验证题是重复测量；8 个题次不解释为 8 次独立进化。不追显著性，不用重抽结果获得结论。
- 报告每次搜索的所选版本、实际代码／装配变异、独立均值与失败。Full−Mechanical 按同一重复编号配对；H*−H0 使用共同独立基线，保留共享基线造成的相关性。
- 原始逐题分数和完整分母保留。已终止失败按注册失败值计入；未观察任务明确为 `null`，不得冒充执行结果。
- 分层报告优化器、任务、构建／QA、独立评分与基线成本。缺失用量、未知费用与空账本明确呈现；请求时长之和不等于墙钟时间。
- 终态后依据真实调用、输入与交付审查机制：自主创建工具或插件须核对实际装配和调用；自填检查、工具注册成功及一次高分均不足以证明通用能力。
- 正负结果均保留，产物按同一真实构建进行安装验收。只有代码可运行、证据闭合时才标记工程验收通过；质量结论单独报告。
