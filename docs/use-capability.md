# Install the capability and complete the task directly

The `bundle.tgz` output by the evolution experiment can be executed through the **DSH native plugin installer → headless Profile → native Agent Loop**. The user only needs to provide a workbook and a task; there is no need to start the optimizer, experiment controller, or scorer. The container on this page provides the Python / openpyxl / LibreOffice runtime dependencies; the model is still invoked by the DSH native adapter.

```text
Reviewed Bundle ── dsh plugin add ── headless Profile
                                      │
Read-only workbook + user task ────────────────▶ DSH Agent
                                      │
                            plugin tools / native tools
                                      │
                          result.xlsx + native session record
```

## Preparation

This entry point is for Bundles that have already been reviewed and trusted; model credentials go directly into the capability container. Unreviewed candidates generated by the optimizer continue to use the experiment system's controlled exit; this entry point must not be used to claim that candidates and credentials are isolated.

Build the spreadsheet runtime image following the README; select a reviewed capability archive. An experiment champion only means it satisfied the scoring rules at the time; it is still necessary to check whether it contains logic such as automatic fixes that violate the capability semantics. Mutation 3 of the new development set has therefore been excluded from distribution.

The following commands are run from the repository root. `CAPABILITY_IMAGE` uses the immutable ID of the local image; the credentials file contains only `VENUS_API_KEY=...`, is placed outside the repository and set as `0600`, and is not copied into the image. When choosing another native model adapter, replace the two model patches; do not change the Agent Loop.

```bash
export CAPABILITY_IMAGE=$(docker image inspect harness-evolution-spreadsheet:local --format '{{.Id}}')
export CAPABILITY_BUNDLE=/absolute/path/to/export/bundle.tgz
export CAPABILITY_CREDENTIALS=/absolute/private/path/venus.env
export TASK_DIR=$(mktemp -d)
export CAPABILITY_CONTAINER="harness-capability-$(basename "$TASK_DIR" | tr '[:upper:]' '[:lower:]')"
mkdir -p "$TASK_DIR/input" "$TASK_DIR/output" "$TASK_DIR/state"
cp /absolute/path/to/my-workbook.xlsx "$TASK_DIR/input/source.xlsx"
printf '%s\n' 'Please process /input/source.xlsx according to my business requirements, preserve the original input, and deliver /workspace/result.xlsx. Replace this with your complete task.' > "$TASK_DIR/task.txt"
```

## Native installation and execution

```bash
docker run --name "$CAPABILITY_CONTAINER" --runtime runc \
  --user "$(id -u):$(id -g)" --cap-drop ALL --security-opt no-new-privileges \
  --read-only --memory 4g --cpus 2 --pids-limit 256 \
  --tmpfs /tmp:rw,exec,nosuid,nodev,size=536870912,mode=1777 \
  --tmpfs "/workspace/.harness-home:rw,nosuid,nodev,size=134217728,uid=$(id -u),gid=$(id -g),mode=700" \
  --env DSH_HOME=/state/dsh \
  --env DSH_MAX_TOKENS_AS_SUCCESS=false \
  --env-file "$CAPABILITY_CREDENTIALS" --workdir /workspace \
  --mount "type=bind,source=$CAPABILITY_BUNDLE,target=/capability/bundle.tgz,readonly" \
  --mount "type=bind,source=$(pwd)/examples/capability,target=/app/examples/capability,readonly" \
  --mount "type=bind,source=$(pwd)/examples/venus,target=/app/examples/venus,readonly" \
  --mount "type=bind,source=$TASK_DIR/input,target=/input,readonly" \
  --mount "type=bind,source=$TASK_DIR/output,target=/workspace" \
  --mount "type=bind,source=$TASK_DIR/state,target=/state" \
  --mount "type=bind,source=$TASK_DIR/task.txt,target=/task.txt,readonly" \
  "$CAPABILITY_IMAGE" bash -c '
    set -euo pipefail
    node /app/examples/capability/install.mjs /capability/bundle.tgz > /state/install.log 2>&1
    exec timeout --signal=TERM --kill-after=10s 600 \
      dsh --profile headless \
        --patch /app/examples/venus/cordis.patch.yml \
        --patch /app/examples/capability/headless.yml \
        --json - < /task.txt
  ' > "$TASK_DIR/events.jsonl" 2> "$TASK_DIR/stderr.log"
```

The install script only invokes the native `dsh plugin add` and reuses the dependency build authorization locked by the image; it does not create an optimization policy or change candidate code. The first installation requires access to the package repository; the execution phase requires model network access. Native dynamic libraries are loaded from `/tmp`, so that tmpfs explicitly allows `exec`, consistent with the declaration of the experiment runner. Only the two public example configuration/install-script directories are mounted; the full project worktree, private evaluation materials, and the Docker socket are not mounted.

Each new task uses an independent `TASK_DIR` and container name, and the container is retained after it ends. Record `docker inspect --format '{{.Id}} {{.State.ExitCode}}' "$CAPABILITY_CONTAINER"`; on failure, inspect the original container and logs, and do not re-run the same command to create a new attempt.

The results are located at `$TASK_DIR/output`. `events.jsonl` is the native bounded event projection; the complete session is saved at `$TASK_DIR/state/dsh`. For the version `0.2.1-rc.4` locked by this project, the terminal state is in the `status` event: `phase=turn_end` and `reason.kind=completed`; the subsequent `final` event provides the text. The container exit code, that terminal state, and the actual files must all be checked together. Newer source documentation places reason in final; its fields cannot be directly applied to the current version. A successful exit does not prove business correctness; on failure, retain the logs and events and do not automatically repeat the model task.

This entry point is a direct capability experience; there is no research scoring step after installation. When research conclusions are needed, return to the fixed contract and independent evaluation process.

## Real acceptance

The [independent installation record](evidence/2026-10-28-standalone-capability.json) uses a newly created non-root container and a fresh DSH_HOME, natively installs the frozen tarball of development experiment mutation 1, and directly invokes the real DeepSeek model. The four steps actually invoked `workbook_inspect → workbook_write → workbook_verify → workbook_inspect`, delivering three formulas and cached values `87.5 / 84 / 171.5`; cell-by-cell checks confirmed that non-target values and intentional blanks were preserved, and the four installed runtime files matched the hashes of the original build artifacts.

This acceptance proves that native installation and the independent task entry point are usable; it does not constitute release approval for that candidate or a new correctness benchmark. The original task acceptance mounted the entire public examples directory; after documentation review it was narrowed to the two required directories, and native configuration assembly was verified separately without repeating the model task. All events, deliverables, and the first startup failure remain in the private acceptance directory; the machine record clearly distinguishes native committed-step usage from underlying request counts.

## Ecosystem basis

- [DSH headless official implementation and usage](https://github.com/deepseek-ai/deepseek-harness/blob/22ddee3792402c3e70ec5f86a63c3e3e895a2f60/packages/bundle/headless/README.md): native one-shot tasks, persistent sessions, JSON terminal state; the latest source and the CLI help of the version installed by this project were checked separately.
- The runtime version of this project is fixed at `0.2.1-rc.4`. This entry point only uses the verified `plugin add`, `--profile headless`, `--patch`, `--json`, and stdin of that version, and does not copy parameters from newer documentation that the installed version does not have.
- In the image, `node-addon-native-custom-loader` places the native binary into a temporary cache before loading; the failure log from the first acceptance, where tmpfs `exec` was missing, is retained, and native acceptance continued after correcting the command without disabling load verification.
