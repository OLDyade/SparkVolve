# Native DSH Plugin Author Capability Integration

Verification date: 2026-10-28. Official source commit `22ddee3792402c3e70ec5f86a63c3e3e895a2f60`; actually installed DSH `0.2.1-rc.4`, Cordis `4.0.5`. The research cross-confirms using official source, package READMEs, runtime declarations, and implementation. Context7 is used for material location; precise behavior is based on the pinned source and actual native execution.

## Integration Decision

```text
Optimizer Host (normal evolution and meta-optimizer share the sdkPreset entry)
  ├─ cordis-host-runner + tool-cordis/host: process-level unique Providers
  ├─ sdk: reuse native Skills registry
  └─ sdk-minimal: explicitly mount native Skills registry
                        │
Evolution Preset        ▼
  ├─ native cordis_inspect_list / cordis_inspect_query
  ├─ native skill tool + independent filesystem Provider
  │    └─ installed agent-preset/skills (default root disabled, watch disabled)
  └─ G author source identity and experiment boundary
                        │
Look up declarations/source on demand → read actual README/types → autonomously edit draft → native probe/QA → independent scoring
```

Reuse the native Creator's discovery and author material paths; do not build another API retrieval protocol, plugin Runtime, or auto-repairer. The method Bundle only explains how to discover interfaces; mutation content, plugin implementation, and composition structure are still chosen by the optimizer based on task evidence. MicroVM does not participate in the assembly prerequisites for this capability.

`sdkPreset(preset, bridge, profile)` requires an explicit Profile, and does not choose a path by guessing whether a service exists. Host Providers are assembled once with the Host; multiple sessions and sub-sessions reuse the native Preset revision. The complete Preset declarations of the installed framework Bundle and method Bundle both include the author plugin, and the program-generated configuration and the distribution configuration use the same structure.

## Official Mechanisms and Actual Boundaries

| Capability | Verified behavior | Experiment implication |
|---|---|---|
| Service / Event | Author declaration directory generated by the pinned distribution package | Finding a declaration does not prove that a custom service is active |
| Config | Host Loader entry directory, config Schema, default definitions, projection limits, and resolvable packageDir | Does not return config instance values; detached Preset subtrees are not in this directory |
| Tool | Visible tool Schema of the requesting Agent | Does not return execution functions; normal sessions cannot see newly added author tools |
| Skill | Native filesystem Provider reads the full text of the installed package on demand | Only restricts the root of newly added Providers; the global Skill mechanism owned by the full sdk remains unchanged |
| Scope / disposal | Tools, Skill Provider, and prompts are released with the registration scope | After a temporary author scope is unloaded, nothing remains; Host Providers are not duplicated as sessions increase |
| G / H | inspection describes the author directory of the current optimizer G | H's build, dependencies, and runtime behavior continue to be verified by frozen candidate QA and native probe |

No `plugin_manager` is opened. The official Skill text is kept as-is, and the new experiment boundary is explicit: the active Profile installation example does not expand experiment permissions; modifications enter candidates through the actual controller tool's draft, commit, and approved probe. No fixed mutation templates or scoring rules were added.

`authoringSources()` records the actual resolved paths, package versions, manifest and entry SHA-256, as well as the complete `lib` / official Skills file list and digests. The model prompt lists only source paths, counts, and digests; the complete list is used for pre-run registration and acceptance. It cites G's actual installed version and does not borrow the latest web version to pass it off as the frozen image source.

## Acceptance and Findings

| Acceptance | Result and boundary |
|---|---|
| Typecheck | Passed |
| Real SDK authoring protocol | Both `sdk` and `sdk-minimal` paths passed; actually called all four inspect types, fully loaded both official Skills, and read real type files via native bash |

These are deterministic acceptances of the framework and native tools, using protocol Providers, and do not claim that the model autonomously succeeded in modification or that business accuracy improved. Real model search, independent validation, and distribution evidence are registered and reported separately.

Real failures and corrections retained during implementation:

- The first `sdk-minimal` activation waited for `skills`: that Profile did not have the full sdk's Skills registry. Corrected to explicit Profile parameters and native Host registration of the minimal Profile.
- The full sdk's Config directory exceeded 100 entries per page: the test client paginates according to native `nextOffset`, without modifying the native Provider or truncating the directory.
- The newly added installed-author assertion failed the first time: the method Bundle's patch fully replaced `preset-evolution.config`, and the original method list overwrote the author capability newly added by the framework Bundle. The program-generated optimizer configuration already had this capability; the old test on the installation path only asserted `evolution_status` and did not cover the author tools. After the method Bundle declaration was completed, the enhanced installation assertion passed. The failure output excerpt is retained locally at `.evolution/native-authoring-integration/installation-assertion-failure.txt`; the excerpt is not presented as a complete raw process log.

A pinned `@babel/parser@8.0.8` was added to development dependencies for standard AST analysis driven by independent author acceptance. Its Node requirement adjusted the repository minimum version to `>=24.11.0`, while actual acceptance still uses 24.16.0. Syntax analysis was not replaced by text matching.
